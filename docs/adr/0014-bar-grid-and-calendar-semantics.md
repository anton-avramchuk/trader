# 0014. Сетка баров и семантика торгового календаря

**Статус:** заменён ADR-0028 (2026-10-01); сохранён как история решений

Дополняет [ADR-0008](0008-trading-calendar-effective-dated.md) и [ADR-0004](0004-candle-time-model.md).

## Решение

Календарь — чистая логика в `trader_engine.calendar` (без БД); в БД хранятся правила (`trading_calendar_rules`), праздники (`trading_calendar_holidays`) и особые дни (`trading_calendar_special_days`), загрузчик — `trader_db.load_trading_calendar`.

- **Окно сессии** не пересекает полночь; правая граница исключающая. Перерывы (клиринг, ночь) — промежутки между окнами. Окно **включает минуту аукциона открытия** (06:59, 08:59, 09:59): сделки аукциона попадают в свечу этой минуты.
- **Принадлежность торговому дню.** Окно с признаком `next_day` (вечерняя сессия до 23.03.2026) относится к следующему **торговому** дню — следующему будню без праздника (или особому дню). Остальные окна — к дню своей даты. Выходная сессия — сама себе торговый день.
- **Торговая неделя** — ISO-неделя торгового дня. Пятничная вечерняя сессия старого режима попадает в следующую неделю.
- **Ожидаемый разрыв** `[a, b)` — интервал, не пересекающийся ни с одной сессией. Любой разрыв, задевающий сессию, — настоящий пропуск данных (для ISS — «минуты без сделок или без данных», ADR-0017).
- **Выходные сессии** хранятся в правиле; для root с `include_weekend_sessions = false` календарь берётся через `excluding_weekend_sessions()`. Праздник на выходную дату отменяет её сессию.
- **Особые дни** (`special_days`) — выходные, торгующиеся как обычный день (рабочие субботы-переносы): окна берутся из будней действующего правила, сессии не помечаются выходными и переживают `excluding_weekend_sessions()`.
- **Сетка баров.** Каждый календарный день сетка строится от `bar_anchor` (07:00 МСК) и заканчивается на следующем якоре. Ячейка обрезается окнами сессий:
  - `start` ячейки — open time бара;
  - `close_time` — конец последнего куска сессии в ячейке (ADR-0004);
  - `is_partial`, если бар короче номинала (обрезан сессией, клирингом или границей сетки). Минута аукциона до якоря даёт отдельный короткий бар (например, 06:45–07:00 из одной минуты 06:59). Пауза внутри ячейки бар не разрывает.
- Ячейка, объединяющая сессии **разных** торговых дней, — ошибка (`ValueError`). Поддерживаемые длительности 15m, 1h, 4h проверены перебором сетки в нескольких режимах и вокруг смены режима.
- Правила одного календаря не пересекаются по датам — гарантируется exclusion-constraint в PostgreSQL (`btree_gist`) и проверкой в движке.

## Калибровка по данным ISS (задача #59)

Начальное расписание было восстановлено по памяти и оказалось неверным для 2020–2021 годов. Оно заменено данными, полученными скриптом `scripts/calibrate_forts_calendar.py` (`collect` → `refine` → `weekends` → `derive`). Метод:

- **Торговые дни** — дневная история всех контрактов BR (объём > 0): праздники — будни без торгов; особые дни — выходные с торгами в дневной истории.
- **Профиль дня** — минутные свечи самого ликвидного контракта: первая и последняя свеча, есть ли торги до 10:00, в 14:00–14:04, начало вечерней, конец основной.
- **Даты переходов** — бисекция между месячными выборками (по одному будню в месяц, 2020-01 … 2026-09).
- **Вечерняя сессия → следующий день** проверено сверкой объёма дня в дневной истории с суммой минутных свечей: в 2020 объём дня **точно** равен «вечер предыдущего дня + день» (включая пятничный вечер → понедельник); в 2025 совпадение приблизительное, но на порядок ближе, чем «тот же день».

### Эпохи (будни, МСК)

| Период | Окна |
|---|---|
| 2020-01-01 … 2021-02-28 | 10:00–14:00 · 14:05–18:45 · вечер 19:00–23:50 |
| 2021-03-01 … 2022-02-24 | + утро 07:00–10:00 |
| 2022-02-25 … 2022-03-01 | без утра |
| 2022-03-02 … 2022-05-29 | только 10:00–14:00 · 14:05–18:45 |
| 2022-05-30 … 2022-07-11 | основная до 18:50 |
| 2022-07-12 … 2022-09-11 | + вечер 19:05–23:50 |
| 2022-09-12 … 2024-06-12 | + утро 08:59–10:00 |
| 2024-06-13 … 2025-01-26 | без утра, аукцион 09:59 (окно 09:59–14:00) |
| 2025-01-27 … 2026-03-22 | утро 08:59–10:00 вернулось |
| 2026-03-23 … 2026-07-13 | единая сессия 08:59–23:50 без клиринга; вечерняя — к текущему дню |
| с 2026-07-14 | единая сессия 06:59–23:50 |

**Выходные сессии** (09:59–19:00) — с 2025-08-16, но не каждые выходные: 30 выходных без торгов записаны как праздники. **Особые дни:** 2021-02-20, 2024-04-27, 2024-11-02, 2024-12-28, 2025-11-01. **Праздники:** 57 будних дней без торгов и 29 выходных без сессии по данным ISS (в 2022 году торги не останавливались надолго).

### Проверка
Календарь сверен с **26 195 реальными свечами** по 34 дням: обе стороны каждого перехода, особые дни и выходные — **0 свечей вне сессий**; пропуски у ликвидных дней 0–7 минут. До калибровки: 14 971 «пропущенная» минута и 17 свечей вне сессий за один ноябрь 2020. Дополнительно: миграция и эталон движка сравниваются тестом на каждой дате 2019–2027.

### Известные ограничения
- **Праздники после 2026-09-28 календарю неизвестны** (данные ISS кончаются там): их нужно добавлять (таблица `trading_calendar_holidays`, редактируется в UI).
- Нерегулярные дни не смоделированы: 2022-02-24 … 2022-03-01 (частичные торги), пятница 2026-03-20 (вечерней сессии не было).
- Минута аукциона (06:59, 08:59, 09:59) появляется не каждый день; окно её включает, поэтому такой день даёт одну «пропущенную» минуту — это нормально.
- Праздники выведены по BR; календарь единый для всего срочного рынка (газ, золото торгуются по той же бирже и в те же дни).
- Дневная история не содержит регулярных выходных сессий (они видны только в минутных свечах) — поэтому выходные без торгов определены отдельным перебором.

## Последствия

- Агрегация (`1m → TF`) берёт границы баров и `close_time` только из `TradingCalendar.bar_slot`.
- Клиринг 14:00–14:05 до 22.03.2026 даёт короткие бары 14:05–14:15 (15m) и 14:05–15:00 (1h) с флагом `is_partial`.
- Скрипт калибровки остаётся в репозитории: его можно перезапустить, когда расписание изменится, и получить новые даты переходов и праздники.
