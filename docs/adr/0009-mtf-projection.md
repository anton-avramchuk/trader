# 0009. Правила multi-timeframe отображения

**Статус:** принято

## Решение
- Source TF задаётся у каждого индикатора/уровня в UI; расчёт — по свечам source TF.
- Старший TF на младшем графике — ступенькой; значение меняется в `available_at` старшего бара; формирующийся старший бар не участвует. Предварительные значения не показываются (в MVP).
- **Младший TF на старшем графике запрещён.**

## Реализация (#29)
- `trader_engine.indicators.mtf.project(chart_bars, source_bars, series)`: значение source-бара `j` доступно барам графика с `close_time >= source[j].close_time` (`available_at` = закрытие source-бара). Для одинакового TF это значение самого бара (оно известно в его закрытие) — поэтому единое правило «значение известно к закрытию бара графика» без утечки: тест (hypothesis + API) проверяет `available_at <= close_time` на каждом баре.
- Формирующийся старший бар не используется: на 15m-барах внутри часа держится значение предыдущего закрытого часа.
- `validate_source_timeframe`: source младше chart → 422 «запрещён».
- API: `GET /indicators` (каталог + JSON-схема параметров), `GET /indicator-values` (chart TF, source TF, диапазон, `as_of`); значения до конца прогрева — `valid = false`; `source_truncated`, если история source TF длиннее 20 000 баров.
