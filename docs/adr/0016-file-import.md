# 0016. Файловый импорт: CSV, JSON, Parquet и пресеты

**Статус:** заменён ADR-0028 (2026-10-01); сохранён как история решений

Дополняет [ADR-0015](0015-import-pipeline.md).

## Решение

**Читатель и маппинг разделены.** Читатели (`read_csv_records`, `read_json_records`, а в worker'е — Parquet через polars) отдают `Record`; `map_records` по `FileMapping` превращает записи в `RawRow` / `RowError` для конвейера. Один и тот же маппинг работает для всех форматов. Логика — в `trader_engine.file_import` (без БД и файловой системы); чтение Parquet и файлов — в `trader_worker.file_sources`.

### FileMapping
Разделитель, заголовок, кодировка, пропуск строк (только CSV); десятичный разделитель; часовой пояс; колонка(и) времени и формат; open/high/low/close/volume; необязательные `trade_count`, `quote_volume`; `timestamp_is_close`. Колонка задаётся именем (при заголовке и в JSON/Parquet) или номером с 0 (CSV; без заголовка — только номера).

### Время
- Время без смещения трактуется в `timezone` маппинга (**по умолчанию `Europe/Moscow`**) и хранится в UTC; ISO со смещением или `Z` — по смещению; `epoch_s` / `epoch_ms` — UTC.
- `timestamp_is_close` сдвигает время на минуту назад: платформа хранит open time (ADR-0004).
- Формат — `strptime`, либо `iso`, `epoch_s`, `epoch_ms`.

### Два вида ошибок
- **Ошибка маппинга** (нет такой колонки, неверный часовой пояс, кодировка, формат времени, пустой файл) находится **до разбора строк**, останавливает импорт и говорит, что исправить: «в файле нет колонок ['<OPN>']; доступные: '<TICKER>', '<OPEN>', …».
- **Ошибка строки** (`missing_column`, `bad_number`, `bad_datetime`) не останавливает импорт: строка попадает в `data_import_errors` с номером физической строки и исходным текстом.

### Пресеты
Таблица `import_presets` хранит сериализованный `FileMapping`. Встроенные (нельзя менять и удалять): `finam` (с заголовком `<DATE>,<TIME>,<OPEN>…`), `finam_no_header` (`TICKER,PER,DATE,TIME,OPEN,HIGH,LOW,CLOSE,VOL`), `iso_utc` (`timestamp` в ISO, UTC). Пользовательские сохраняются через `save_preset`.

**Не проверено:** формат Finam взят по стандартной выгрузке (`YYYYMMDD` и `HHMMSS`, время московское, начало свечи, разделитель запятая). У Finam в настройках выгрузки есть разделитель, формат даты и время начала/конца свечи — при отличиях пресет правится через `overrides` (`delimiter`, `timestamp_is_close` …) или сохраняется свой. Время вида `90000` (без ведущего нуля) не поддерживается — строка получит `bad_datetime`.

### Задача `import.file`
Параметры: `contract_id`; `file` (имя внутри каталога импорта); `format` (`csv` / `json` / `parquet`, по умолчанию по расширению); **ровно одно** из `preset` / `mapping`; необязательные `overrides` (поля маппинга поверх пресета); `allow_non_positive_prices`. Провайдер записи об импорте — `csv`. Результат задачи — id импорта, id версии и отчёт.

### Безопасность и ошибки задачи
- Файлы читаются **только из каталога импорта** (`TRADER_IMPORT_DIR`, в Compose — общий том `imports`); `../` и абсолютные пути отвергаются.
- Ожидаемые ошибки пользователя (`JobFailed`) записываются в задачу коротким сообщением **без traceback**; неожиданные — с traceback.

### Ограничения
JSON и Parquet читаются целиком в память (годовой файл 1m одного контракта — десятки МБ). Предпросмотр файла для мастера (`preview_csv`, определение разделителя) есть в движке; HTTP-эндпоинт и загрузка файла появятся вместе с API (#12) и UI импорта.
