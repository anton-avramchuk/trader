# 0025. Historical Analogues (MVP-6): PIP, DTW, поиск аналогов

**Статус:** принято (реализация — MVP-6; решения по итогам раунда проектирования, issue #44)

Развивает spec §27–§29, §50–§51 и ADR-0022 (PIP Engine — «позже, второй источник точек»), ADR-0023 (outcomes, de-overlap, bootstrap, кэш на лету).

## Решение

**Запрос.** Два входа в один движок: (1) подтверждённое вхождение паттерна или событие уровня (клик на графике); (2) произвольное окно последних N баров («что сейчас на графике», N по умолчанию 60, настраивается). Запрос всегда привязан к моменту `as_of` (в replay — текущий бар) и использует только данные до него.

**Представление.** DTW считается по **PIP-точкам**, а не по сырым close (spec §27). PIP Engine: окно → ровно *k* опорных точек (по умолчанию 9; режим «порог ошибки» — позже), итеративный выбор точки с наибольшим вертикальным отклонением от линии между уже выбранными соседями. Окно кандидата из истории режется тем же числом баров и тем же PIP. Сырой режим не делается.

**Нормализация.** По умолчанию **ATR**: цена точки минус цена первой точки, делённая на ATR14 на последнем баре окна; время — в барах, масштабируется к [0,1] по ширине окна. Опция — **percentage** (изменение от первой точки в %). Absolute и z-score не делаются (spec требует минимум percentage и ATR).

**DTW.** Собственная реализация на numpy, без новых зависимостей: классический DTW по паре (время, цена) с полосой Сакоэ–Чибы (по умолчанию 20% длины), `normalized_distance` = накопленная стоимость / длина пути. Similarity = `1 / (1 + normalized_distance)` — число в (0, 1], сравнимо между запросами только при одинаковых параметрах. Результат `PatternMatch`: `historical_event_id`, `distance`, `normalized_distance`, `similarity`, `time_alignment` (путь выравнивания).

**Область поиска.** Параметр запроса `scope`: `instrument` (по умолчанию — тот же root и TF) или `all` (тот же TF по всем загруженным инструментам). Всегда: только история, доступная на `as_of` (`available_at` не позже), окно самого запроса и пересекающиеся с ним вхождения исключены. Это единственная защита от look-ahead и она проверяется тестом на перестановку будущего.

**Отбор.** Top-K (по умолчанию K = 20) по расстоянию + порог `max_distance`; de-overlap как в ADR-0023 — аналоги одного инструмента ближе окна запроса друг к другу считаются одним (остаётся ближайший). Малый эффективный N — предупреждение, без «точных» чисел.

**Исходы аналогов.** Для каждого аналога считаются outcomes из MVP-5 (return, MFE, MAE, в ATR и %, горизонты, флаги пересечений, censoring) от точки подтверждения; агрегат по аналогам — медиана и CI (block bootstrap, ADR-0023), baseline MVP-5 для сравнения. Траектории аналогов после точки входа переводятся в ATR и показываются перцентилями 25/50/75 (spec §51).

**Хранение.** Не персистим: PIP-представления, матчи и траектории считаются на лету из `engine_events` и свечей; кэш в процессе по `(dataset_version, версии движков, params_hash, as_of, запрос)`. Отступление от spec §29/§60 принято, как в ADR-0023; при медленных запросах — отдельная задача на материализацию PIP-векторов истории (ключ кэша станет ключом таблицы).

**API.** `GET /analogues` — запрос (событие или окно), `scope`, `k`, `max_distance`, `normalization`, `pip_points`, `band`, `horizon`, `as_of`; ответ: матчи (формация, точка подтверждения, similarity, исход), агрегат, траектории и перцентили, предупреждения.

**UI.** Панель «Аналоги» в Chart и Replay: кнопка у выбранного паттерна/уровня и для текущего окна; список матчей (формация, similarity, return, MFE/MAE, инструмент и дата), наложение траекторий после текущей точки с перцентилями 25/50/75. Показ матча на собственном графике — позже.

**Тесты.** Unit: PIP на фикстурах, DTW на известных векторах (идентичные = 0, сдвиг/растяжение, симметрия, полоса), нормализации; свойства: расстояние инвариантно к масштабу/сдвигу цены при ATR/percentage-нормализации; leakage — результат на `as_of` не зависит от будущего; детерминизм; интеграция с PostgreSQL на цепочке движков; UI в Playwright.

## Декомпозиция
1. PIP Engine и нормализации (ATR, percentage) (#123).
2. DTW-ядро: полоса, нормализованная длина, similarity, выравнивание (#124).
3. Библиотека кандидатов: PIP-представления вхождений и окон, scope, причинный срез `as_of` (#125).
4. Поиск: Top-K, порог, de-overlap, исходы и траектории аналогов, агрегат и перцентили (#126).
5. API `/analogues` с кэшем (#127).
6. UI: панель «Аналоги» и наложение траекторий (#128).
7. Тесты: leakage, свойства, регрессия, интеграция (#129).
