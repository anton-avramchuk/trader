# 0015. Конвейер импорта свечей 1m

**Статус:** принято

Дополняет [ADR-0005](0005-bitemporal-raw-dataset-versions.md) и [ADR-0002](0002-postgres-job-queue.md).

## Решение

Источник (CSV, ISS…) только разбирает данные в `RawRow` / `RowError`. Остальное общее: валидация (`trader_engine.ingest`), покрытие календарём (`trader_engine.coverage`), запись, отчёт и dataset version (`trader_db.run_candle_import`). В worker'е — `make_import_handler` / `register_import_job`.

### Атомарность
Импорт пишется **одной транзакцией**: свечи, конфликты, ошибки строк, итог и dataset version. Raw-строки неизменяемы и не удаляются; частично записанный сорвавшийся импорт оставил бы «активные» свечи, которых нет ни в одной версии, а повторный импорт посчитал бы их дубликатами. Запись об импорте создаётся отдельной транзакцией заранее — чтобы при сбое или отмене пометить её `failed`. Прерванные попытки той же задачи (worker упал) помечаются проваленными при следующем запуске (`params.job_id`).

### Валидация строки
Первая нарушенная проверка даёт код причины; строка не пропадает, а сохраняется в `data_import_errors` (не более 5000, остальные — в счётчике `error_counts`).

| Код | Условие |
|---|---|
| `missing_field` | нет времени или одного из open/high/low/close/volume |
| `bad_timestamp` | время без часового пояса |
| `not_minute_aligned` | секунды или микросекунды не равны нулю |
| `non_finite_value` | NaN / Infinity |
| `value_out_of_range` | вне диапазона колонки (цена ≥ 1e10, объём ≥ 1e16, `trade_count` вне int) |
| `value_too_precise` | больше 8 знаков после запятой — PostgreSQL округлил бы молча |
| `non_positive_price` | цена ≤ 0 (можно разрешить параметром `allow_non_positive_prices`) |
| `negative_volume` | объём < 0 |
| `high_lt_low`, `high_lt_open_close`, `low_gt_open_close` | нарушены соотношения OHLC |
| `conflicting_duplicate` | в источнике несколько строк с одним временем и разными значениями (отвергаются все) |
| коды парсера | например `parse_error` |

Время нормализуется в UTC. Полностью совпавшие строки с одним временем схлопываются (`duplicates_in_file`). Нарушение порядка — не ошибка: строки сортируются, число нарушений идёт в `warnings.out_of_order_rows`.

### Покрытие
- **Пропуски** считаются по окнам сессий календаря в диапазоне от первой до последней свечи источника; ночь, выходные, клиринг и праздники пропусками не являются. В отчёте — число интервалов, число минут и первые 50 интервалов.
- **Свечи вне сессий** не отвергаются, а считаются (`warnings.outside_session_rows`, пример — `outside_session_sample`). Причина: расписание до 23.03.2026 не проверено (ADR-0014), и этот счётчик — способ его сверить с данными.
- Анализ идёт по загруженному файлу, а не по объединению с БД.

### Итог
- Отчёт: `rows_total/valid/rejected`, `inserted`, `duplicates` (в файле + в БД), `conflicts`, `error_counts`, `range`, `min_price`, `max_price`, `missing`, `warnings`, `dataset_version_id`.
- **Dataset version создаётся, только если что-то вставлено.** Если импорт принёс лишь дубликаты и конфликты, данные не изменились; версию создаст принятие конфликтов.
- Отмена задачи и остановка worker'а откатывают импорт целиком.

### Производительность
Новые свечи пишутся через `COPY` (~74 тыс. строк/с против ~14 тыс. у executemany; исключения `psycopg` переводятся в SQLAlchemy). Профиль года 1m (288 тыс. строк): валидация ~5 с, запись ~6 с, всего ~12 с.
