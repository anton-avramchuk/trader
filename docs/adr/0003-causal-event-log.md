# 0003. Каузальная модель вычислений и неизменяемый лог событий

**Статус:** принято

## Контекст
Нужны и batch-расчёт по годам истории, и replay «как система знала тогда», и одна реализация для UI, notebook и бэктеста (§60). Раздельные batch/online реализации — источник расхождений и look-ahead.

## Решение
Каждый алгоритм — каузальная инкрементальная машина `update(bar) -> events`. Batch — прогон её по истории. Результат — неизменяемый event log с `available_at`, `algorithm_version`, `params_hash`, `dataset_version_id`. Пересмотры (последнее колено ZigZag, отмена кандидата паттерна) — новые события `revised`/`invalidated`, а не UPDATE.

Векторные реализации допустимы для заведомо каузальных индикаторов при прохождении теста префикс-инвариантности `f(data[:t])[-1] == f(data)[t]` (hypothesis, случайные t).

## Последствия
- Visual replay = фильтр `available_at <= t`.
- Online replay (повторный прогон и сравнение с логом) — главный тест против look-ahead.
- Алгоритмы сложнее писать, чем чисто векторные.
