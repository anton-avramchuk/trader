# 0026. Forecast (MVP-7): empirical, KNN, калибровка

**Статус:** принято (реализация — MVP-7; решения по итогам раунда проектирования, issue #45)

Развивает spec §34–§35, ADR-0013 (статистическая корректность), ADR-0023 (исходы, de-overlap, bootstrap), ADR-0025 (аналоги). Spec §388: Pattern Quality, Historical Similarity, Statistical Reliability и Forecast Probability — разные величины и в одно число не сливаются.

## Решение

**Методы.** Два независимых прогноза рядом, без смеси в одно число и без ML:
- **Empirical** — распределение исходов MVP-5 для вхождений того же типа и направления (и режима — переключателем) на истории, известной на `as_of`. Требует вхождение-запрос; для запроса-окна не строится.
- **KNN** — исходы ближайших аналогов MVP-6 (DTW), равные веса, после de-overlap. Работает и для вхождения, и для окна.
Каждый метод сообщает свой N, эффективный N и предупреждения; расхождение методов — информация для пользователя, а не ошибка.

**Состав прогноза на каждом горизонте** (5/10/20/50 баров торгового времени, настраивается):
- вероятности `P(return ≥ +k·ATR)` и `P(return ≤ −k·ATR)` для порогов `k ∈ {0.5, 1, 2}` ATR на входе (в процентах — переключатель, как в ADR-0023);
- медиана и квантили дохода 10/25/75/90, медианные MFE и MAE;
- 95% CI вероятностей (block bootstrap, ADR-0023) и среднего; `n_raw`, `n_effective`, `censored`;
- `contributing_features` — не в MVP-7 (нет ML; вклад признаков осмыслен только для моделей).
Горизонт без достаточной выборки (эффективный N < порога ADR-0023) — предупреждение, без «точных» чисел.

**Направление.** Исходы Empirical — в направлении события (как MVP-5), KNN — в сыром (как ADR-0025); прогноз явно помечает, в каком направлении выражен каждый метод, а UI показывает их в одной системе (вверх/вниз по цене).

**Триггер и хранение.** Только по запросу — для выбранного вхождения или текущего окна, `as_of` причинный; считается на лету, кэш по версиям прогонов и параметрам, не персистится (как ADR-0023/0025). Автоматических прогнозов на каждое событие, сохранения и алертов `Forecast Updated` в MVP-7 нет.

**Калибровка.** Walk-forward: для каждого исторического вхождения прогноз строится только по данным до него (`as_of = available_at`), затем сравнивается с реализованным исходом. Отчёт — Brier score и reliability-таблица (корзины предсказанных вероятностей против частоты) по порогам и горизонтам, с CI и числом событий; сравнение с baseline «безусловная частота». Отчёт — отдельный эндпоинт и блок «Надёжность модели» в UI, чтобы вероятности не принимались на веру.

**API.** `GET /forecast` (вхождение или окно, `run_id`/`query_run_id`/`key`, горизонты, пороги, единицы, режим-фильтр, `as_of`, параметры аналогов); `GET /forecast/calibration` (тип/направление, горизонт, период).

**UI.** Панель Forecast в Chart/Replay рядом с блоками «Исторически» и «Аналоги»: две колонки (Empirical, KNN), таблица вероятностей и квантилей по горизонтам, предупреждения; блок «Надёжность модели» (Brier, reliability). Распределение — компактная гистограмма исходов.

**Тесты.** Unit на крафтовых исходах (вероятности порогов, квантили, CI, малая выборка); leakage — прогноз на `as_of` не зависит от будущего; детерминизм; согласованность с MVP-5/6 (empirical равен MVP-5, KNN — исходам аналогов); калибровка на синтетике с известной вероятностью (Brier близок к теоретическому, reliability около диагонали); интеграция с PostgreSQL; UI в браузере.

## Декомпозиция
1. Ядро Forecast: вероятности порогов, квантили, CI, предупреждения по набору исходов (#138).
2. Empirical-прогноз: выборка по типу, направлению и режиму, причинный срез (#139).
3. KNN-прогноз по аналогам MVP-6 (#140).
4. API `GET /forecast` с кэшем (#141).
5. Walk-forward калибровка: Brier, reliability, `GET /forecast/calibration` (#142).
6. UI: панель Forecast и «Надёжность модели» (#143).
7. Тесты: leakage, калибровка на синтетике, согласованность, интеграция (#144).
