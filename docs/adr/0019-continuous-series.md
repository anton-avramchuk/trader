# 0019. Continuous-серия: расписание роллов, ratio, склейка при чтении

**Статус:** принято

Реализует [ADR-0007](0007-futures-continuous-ratio-weekly-roll.md) поверх баров [ADR-0018](0018-bar-aggregation.md).

## Расписание роллов (`trader_engine.continuous`)
- Контракты root сортируются по экспирации (`last_trade_date`, иначе `expiration_date`). Ролл `A → B` — в **начале последней торговой недели, с которой до экспирации A остаётся не менее N торговых дней** (`roots.roll_trading_days`; экспирация не считается, торговый день — по календарю ADR-0014).
- Момент ролла `rolled_at` — первый момент торговой недели (`trading_week_bounds`). Бары любого TF, включая `1w`, не пересекают эту границу: торговый день не делится, неделя начинается с понедельника (пятничная вечерняя и выходные сессии — часть торгового дня понедельника).
- Расписание детерминировано, не зависит от порядка входа; роллы обязаны идти строго по возрастанию (иначе ошибка — серии слишком близки по экспирации).

## Ratio и события
- `ratio = close(B) / close(A)` в **последний общий торговый день**, завершившийся до `rolled_at` (дневные бары `1d`, окно поиска — 10 последних дней). Основание сохраняется в событии (`basis_trading_day`, `from_close`, `to_close`).
- `roll_events (root, from, to, rolled_at, ratio, basis…, available_at)`; `available_at = rolled_at`: ratio опирается только на данные до ролла.
- Ролл без общего дня ждёт: он и все следующие не применяются, серия остаётся на прежнем контракте. В расписание входят только контракты, у которых есть дневные бары.
- `update_rolls` идемпотентна: события пересчитываются по текущим данным, лишние (сменился N, появился контракт) удаляются. Вызывается в конце задачи `aggregate.contract`.

## Склейка при чтении
Сегмент выбирает бары по **времени закрытия** (`close_time` в `(roll_i, roll_{i+1}]`), а не по open time: бар сетки может начаться чуть раньше ролла (4h с 16:00 при старте недели в 16:05), но целиком лежит после него. Найдено регрессионным тестом на реальных данных ISS (#18).

Continuous **не материализуется**. `read_continuous(root, tf, [start, end))` берёт бары контрактов из `derived_candles` по сегментам `[roll_i, roll_{i+1})` и умножает цены сегмента на множитель — произведение ratio всех **следующих** роллов (текущий контракт — множитель 1, объём не масштабируется). Поэтому:
- относительные изменения внутри сегмента совпадают с исходным контрактом;
- новый ролл меняет только множители, историю переписывать не нужно;
- `to_current_scale` / `to_contract_scale` переводят цену между масштабом сегмента и текущим (для отображения уровней).

## Последствия
- Абсолютные уровни исторических сегментов «плавают» с каждым роллом; сохранять уровни надо вместе с контрактом и моментом (пересчёт через сегмент).
- Выходные сессии в серии по умолчанию исключены — флаг `include_weekend_sessions` учитывается ещё при сборке баров контракта.
- Пока у следующего контракта нет данных до ролла, серия «застревает» на текущем; это видно по отсутствию события.
