# 0018. Агрегация минутных свечей в бары 15m / 1h / 4h / 1d / 1w

**Статус:** заменён ADR-0028 (2026-10-01); сохранён как история решений

Реализует [ADR-0004](0004-candle-time-model.md) и [ADR-0006](0006-iss-1m-source-aggregated-timeframes.md) поверх календаря [ADR-0014](0014-trading-calendar.md).

## Алгоритм (`trader_engine.aggregation`)
Чистая потоковая логика без БД: `BarAggregator.push(candle)` возвращает закрытые бары, `finish()` — последний, если он закрыт.
- **Границы берутся только из календаря.** Intraday — ячейки сетки (`TradingCalendar.bar_slot`, сетка от `bar_anchor`), `1d` — торговый день, `1w` — торговая неделя (понедельник).
- Бар короче номинала (обрезан сессией, клирингом, границей сетки) получает `is_partial`; `close_time` — конец последнего куска сессии в ячейке.
- Ячейка не смешивает торговые дни (иначе ошибка календаря) — поэтому в рабочих окнах вечерней/выходных сессий стоит `next_day` (миграция 0008): выходные сессии относятся к торговому дню понедельника.
- Свечи вне сессий календаря в бары не попадают и **считаются** (`skipped_outside_session`, первые 1000 моментов — в отчёте).
- Скорость: слот кэшируется, пока следующая свеча попадает в тот же кусок ячейки (`BarSlot.contains`); без кэша 90 % времени уходило на `bar_slot`.

## Формирующийся бар не публикуется
ISS не отдаёт минуты без сделок, поэтому по отсутствию следующей свечи закрытость бара не определить. Последний бар входа выдаётся, только если `close_time <= complete_until`. Индикаторы и стратегии никогда не видят бар, который ещё может измениться.

`complete_until` для контракта (worker): конец последней свечи; если загружено окно ISS, то конец последнего дня окна; но не позже «сейчас».

## Хранение и пересборка (`trader_db.derived`)
- `derived_candles` — бары всех TF (PK `contract_id, timeframe_code, timestamp`), `built_from_version_id` — версия датасета 1m, из которой построены.
- `derived_builds` — журнал сборок: версия источника, отпечаток календаря, флаг выходных сессий, версия алгоритма, `complete_until`, режим, отчёт.
- **Инкрементальность.** Пересборка идёт от начала торговой недели, где появились новые минутные свечи или лежит последняя свеча (её бар мог быть не закрыт); строки с `trading_day` не раньше этого дня удаляются и пишутся заново (`COPY`).
- **Полная пересборка**, если изменился отпечаток календаря, `include_weekend_sessions`, `ALGORITHM_VERSION` либо задан `force`.
- **`noop`**, если версия источника та же и `complete_until` не вырос.
- Сборка одного TF — одна транзакция: читатель видит либо старые, либо новые бары.

## Задача `aggregate.contract`
Параметры: `contract_id`; `timeframes` (по умолчанию все пять); `force`. Импорт, добавивший свечи (новая версия датасета), ставит задачу в той же транзакции; ожидающая задача контракта не дублируется (`enqueue_aggregation`). Загрузка ISS из нескольких кусков порождает одну задачу, а не по одной на кусок.

## Последствия
- Смена календаря (новая эпоха, праздник) автоматически приводит к пересборке при следующем запуске — по отпечатку.
- Принятие конфликтов создаёт новую версию датасета; сборку для неё нужно запускать явно (автопостановка после `import_conflicts` — отдельная задача).
- Бары 1w неполной (текущей) недели не публикуются, пока неделя не закрыта.
