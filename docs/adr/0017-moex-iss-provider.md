# 0017. Провайдер MOEX ISS: контракты и загрузка минутной истории

**Статус:** заменён ADR-0028 (2026-10-01); сохранён как история решений

Реализует [ADR-0006](0006-iss-1m-source-aggregated-timeframes.md) на стороне загрузки; данные идут через конвейер [ADR-0015](0015-import-pipeline.md).

## Интерфейс
`trader_providers.HistoricalDataProvider` (`list_contracts`, `candle_range`, `get_historical_candles`, `close`) — историческая часть интерфейса из spec §10. Потоковую часть (`subscribe_realtime`) добавит провайдер T-Invest; ISS её не реализует. Провайдер возвращает `ProviderContract` и `RawRow` / `RowError`, поэтому внутренняя система не зависит от формата ISS.

## Факты об API
- Свечи: колонки идут в порядке **`open, close, high, low, value, volume, begin, end`** (не OHLC); читаются по имени. `begin` — открытие свечи по Москве. Страница — 500 строк, дальше `start=N`; читаем до **пустой** страницы, а не полагаемся на размер страницы.
- **ISS не отдаёт минуты без сделок.** У неликвидного контракта ночью в данных дыры. Поэтому «пропуски» в отчёте импорта — это «минуты без сделок или без данных», а не признак ошибки; значимы только длинные пропуски внутри торгов.
- Повторяющиеся SECID ISS разрешает сам: старый контракт переименован (`BRZ0` — 2020, `BRZ0_2010` — 2010).
- Описание `/iss/securities/{SECID}` даёт `ASSETCODE`, `LSTTRADE`, `LSTDELDATE` (экспирация) и диапазон истории по площадке `RFUD`; `candleborders` — первую и последнюю минутную свечу.
- Справочник серий перечисляет **действующие** контракты с `asset_code`; по нему определяется префикс SECID (для золота `GD`, а не `GOLD`).
- В свечи попадают сделки аукциона открытия (первая свеча в 09:59, 08:59, 06:59).

## Обнаружение контрактов
Кандидаты — `префикс + буква месяца (FGHJKMNQUVXZ) + цифра года` за каждый год диапазона; для каждого запрашивается описание. Контракт принимается, если `ASSETCODE` совпадает с базовым активом и год экспирации отличается от года кандидата не больше чем на 1 (иначе это контракт десятилетней давности, и пробуется `SECID_год`). Ключ контракта в БД — `(root, дата экспирации)`; SECID и код у поставщика — атрибуты. Префикс можно задать вручную (`secid_prefix`), если у актива нет действующих серий.

## Надёжность клиента
Ограничение частоты (не чаще одного запроса за 0,25 с), повторы при `429`, `5xx` и обрывах соединения (до 4 повторов, экспоненциальная пауза, `Retry-After` учитывается); остальные `4xx` — сразу ошибка с понятным текстом. Часы и `sleep` инъектируются, поэтому тесты не ждут по-настоящему.

## Загрузка: возобновляемая и идемпотентная
- Покрытие = объединение окон дат (`params.window`) **завершённых** импортов провайдера по контракту. Упавшие и выполняющиеся импорты покрытием не считаются.
- Загружаемое окно = от первой до последней доступной свечи, **но не позже вчерашнего дня** (сегодняшний неполон: его добирает T-Invest и ночная сверка, #20–#21). Из окна вычитается покрытие, остаток режется на куски по 92 дня; **каждый кусок — отдельный атомарный импорт** со своей версией датасета.
- Сорвавшаяся загрузка продолжается с первого незагруженного куска; повторный запуск догружает только недостающее (проверено: второй запуск — 0 кусков, расширение окна — только новые дни, дубликатов 0).
- Отмена задачи проверяется между страницами; идущий кусок откатывается целиком.

## Задачи
- `iss.sync_root` (`root_id`; `from_year` = 2020; `to_year` = следующий год; `secid_prefix`; `enqueue_imports` = true): находит контракты, заводит их в БД с кодом ISS и ставит `import.iss` на каждый (без дублей, если такая задача уже в очереди).
- `import.iss` (`contract_id`; необязательные `from` / `till`): загружает историю одного контракта.

## Производительность
Живой замер: 5351 минутная свеча за 7 с (~760 строк/с вместе с валидацией и записью); перебор 24 месяцев кандидатов — 10 с. Полная история трёх активов за 6 лет — порядка часов, но однократно; дальше догружаются только новые дни.

## Проверка на настоящем ISS
Тесты `libs/providers/tests/test_iss_live.py` выключены по умолчанию (CI не зависит от внешней сети): `TRADER_LIVE_TESTS=1 uv run pytest tests/test_iss_live.py`. Они фиксируют факты выше и заметят, если ISS изменит формат.

## Обнаружено при проверке
Реальное расписание FORTS отличается от начального календаря (ADR-0014): в ноябре 2020 не было утренней сессии, вечерняя начиналась в 19:00, потом в 19:05; основная сессия заканчивалась в 18:45, потом в 18:50. Календарь нужно откалибровать по данным (отдельная задача); до этого отчёт импорта показывает много «пропусков» и «свечей вне сессий» за 2020–2021 годы.
