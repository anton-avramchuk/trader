# 0027. Backtesting (MVP-8): шаблон стратегии, исполнение, walk-forward

**Статус:** принято (реализация — MVP-8; решения по итогам раунда проектирования, issue #46)

Развивает spec §40–§41, §53–§54, ADR-0003 (причинный лог событий), ADR-0007 (continuous, ролл), ADR-0013 (пессимистичный неоднозначный бар, заблокированный test-период, журнал запросов), ADR-0023 (outcomes).

## Решение

**Объём проекта.** Paper Trading (MVP-9) и Live Trading (MVP-10) **исключены из проекта** (решение владельца, 2026-10-01; задачи #47 и #48 закрыты как не планируемые). Бэктест — конец цепочки: брокерского интерфейса, режимов PAPER/LIVE, realtime и алертов нет. Упоминания paper/live в spec — история замысла; действует этот ADR вместе с ADR-0024.

**Стратегия — параметрический шаблон «вход по событию»**, без кода пользователя:
- *источник сигнала*: подтверждённое вхождение паттерна (типы), либо касание или пробой уровня (ADR-0023); сигнал известен на `available_at`;
- *сторона*: по направлению события или обратная (fade);
- *фильтры*: режим (тренд × волатильность, ADR-0023), диапазон качества, период; фильтр по прогнозу — позже;
- *выходы*: стоп (в ATR либо уровень отмены паттерна), цель (в ATR либо цель паттерна), ограничение по времени (баров), что сработает раньше;
- *размер*: одна позиция на инструмент, фиксированное число контрактов; пирамидинга и реверса нет; сигналы при открытой позиции пропускаются. Риск-менеджмент (лимиты дня, экспозиции) — не в MVP-8.

**Исполнение.** Сигнал виден на закрытии бара (`available_at`) → **вход по open следующего бара** в реальном фронтовом контракте (цены контракта, не ratio-скорректированные); уровни стопа и цели считаются на continuous-серии и переводятся в цены контракта множителем ratio на момент входа. Стоп и цель проверяются со следующего за входом бара; если в одном баре достигнуты и стоп, и цель — пессимистично сначала стоп + флаг `ambiguous_bar` (ADR-0013); гэп через стоп исполняется по open. Выход по времени — close бара лимита.

**Издержки.** Комиссия за контракт на сторону (в ₽, настраивается), спред (полуспред в тиках на каждую сторону) и проскальзывание (тики на сторону). **Ролл**: открытая позиция при смене фронтового контракта закрывается в старом и открывается в новом на момент ролла, с полными издержками обеих сторон; ролл показывается отдельной строкой в отчёте.

**PnL.** Валовый — в тиках и в валюте котировки (USD); в ₽ — по историческому `step_price` контракта на день сделки (ADR-0007, дневная история ISS); комиссия в ₽. Если `step_price` дня неизвестен — берётся ближайший предыдущий известный, сделка помечается `step_price_estimated`.

**Метрики:** Net/Gross доходность, Max Drawdown, Sharpe, Sortino, Win Rate, Profit Factor, число сделок, средняя сделка, MFE и MAE по сделкам, equity curve (по закрытым сделкам и по барам). Метрики — не единственный критерий: в отчёте всегда показываются число сделок, доли ambiguous bar и ролловых сделок, предупреждение о малой выборке (порог — как в ADR-0023).

**Валидация.** Walk-forward: окна `train → validation` по торговым дням скользят с шагом; параметры из заданной сетки выбираются **только по train/validation** окна (целевая метрика настраивается; по умолчанию Profit Factor с минимумом сделок), результат каждого окна хранится отдельно. **Финальный test-период** задаётся до запуска, исключён из всех окон и **блокируется**: на связку (инструмент, TF, стратегия-семейство) он открывается один раз; повторный запуск отклоняется, разблокировка — явная, с записью в журнал. **Журнал запросов**: каждый запуск (включая неудачные и отклонённые) пишется с параметрами, периодом и признаком касания test-периода — чтобы число перебранных вариантов было видно при оценке результата (множественное тестирование).

**Хранение.** В БД: эксперимент (версия данных `dataset_version_id`, версии движков и стратегии, параметры, инструмент, TF, периоды train/validation/test, результат), сделки (вход, выход, причина, ссылка на вхождение, издержки), equity, окна walk-forward, журнал и блокировки test. Воспроизводимость: эксперимент с теми же версиями даёт те же сделки (детерминизм).

**Запуск.** Задача очереди `backtest.run` (ADR-0002) — прогресс по WebSocket; API: создание, список, результат, сделки, equity, окна, журнал.

**UI.** Страница Backtest (маршрут есть): инструмент, TF, период, шаблон стратегии и его параметры, издержки, walk-forward/test; результат — метрики, equity, таблица сделок, окна walk-forward. Drill-down сделки: вход, выход, причина, паттерн/событие, ближайший уровень, режим на входе, прогноз на момент входа (по запросу, ADR-0026) и переход к участку графика (Chart/Replay с `as_of`).

**Тесты.** Unit на синтетических барах с известным PnL (вход, стоп, цель, гэп, неоднозначный бар, время, ролл, издержки); leakage — сделки до момента T не меняются при искажении баров и событий после T (инвариантность по префиксу); решения не используют данные позже `available_at`; walk-forward — параметры окна не зависят от будущего, test заблокирован; детерминизм; регрессия на фиксированном наборе; интеграция с PostgreSQL; UI в браузере.
