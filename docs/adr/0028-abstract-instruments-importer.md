# 0028. Абстрактные инструменты и сервис importer

**Статус:** принято 2026-10-01 (решение владельца); реализация — этап «Data v2»

Заменяет модель данных ADR-0004…0008 и ADR-0014…0019 (контракты, роллы, continuous-склейка, `step_price`, сырые 1m, bitemporal-версии, календарь и агрегация баров в ядре). ADR-0024 (отказ от T-Invest) и ADR-0027 (бэктест) остаются, но упрощаются (см. ниже).

## Решение

**Ядро работает с абстрактными данными.** Единица данных — **инструмент** (тикер) со свечами по таймфреймам. Никаких фьючерсных понятий в ядре: нет контрактов, экспираций, роллов, склейки, ratio/factor, `step_price`, торгового календаря. Если у источника есть фьючерсы, они для ядра обычные тикеры (`NG1`, `BR1`, `SBER` — всё равно), цены без корректировок, гэпы остаются как есть.

**Importer — отдельный HTTP-сервис** (`apps/importer`) и единственный источник данных. Он только отдаёт исторические данные источника, ничего не хранит и не знает про ядро. Для США позже будет такой же сервис с тем же контрактом.

Контракт importer (версия 1):
- `GET /tickers` → список `{ticker, name, currency, tick_size, timezone, timeframes[], first_date, last_date}`.
- `GET /history?ticker=&tf=&from=&to=` → `{candles: [{t, o, h, l, c, v}], next_from}`: готовые **закрытые** свечи таймфрейма (`15m, 1h, 4h, 1d, 1w`) в `[from, to)`, `t` — начало свечи (UTC), по возрастанию; `next_from` — продолжение при превышении лимита страницы. Агрегации в ядре нет: что отдал importer, то и график.
- `GET /health`.
Пользователь жмёт «подгрузить» → в ядре создаётся задача с периодом дат → worker ходит в importer → свечи записываются. Первая реализация — прокси к MOEX ISS; как именно источник даёт готовые таймфреймы и тикеры — деталь importer, ядро её не видит.

**Модель ядра.**
- `instruments`: `id`, `ticker` (уникален), `name`, `currency`, `tick_size`, `timezone`, `tick_value` (стоимость тика в валюте счёта, необязательна), `source` (какой importer), служебные поля.
- `candles`: `(instrument_id, timeframe, open_time)` — первичный ключ; `close_time`, `open/high/low/close`, `volume`, `trading_day` (дата `open_time` в `timezone` инструмента; от неё считаются дневные/недельные пивоты и дни walk-forward). Загрузка за период перезаписывает свечи (upsert).
- `candle_loads`: журнал загрузок — инструмент, TF, период, число строк, источник, время.
- Версий датасета и bitemporal нет. Воспроизводимость обеспечивают отпечатки обработанных баров в прогонах движков (ADR-0021): если история изменилась, прогон создаётся заново, старые события остаются.
- Остаются без смены смысла: очередь задач (ADR-0002), лог событий движков, индикаторы, профили графика, ручные сетки Фибоначчи, бэктесты — но ключ `root_id/contract_id` заменяется на `instrument_id`.

**Бэктест упрощается.** Ряд один, цены те же, что видит график: `factor` и ноги на ролле исчезают (сделка — один вход и один выход), ролловых издержек нет. PnL — тики и пункты цены; в валюте счёта — `ticks × tick_value × количество`, если `tick_value` задан (иначе только тики и пункты).

**Что удаляется.** Таблицы и код: contracts, roots (заменяется instruments), roll_events, contract_step_prices, raw_candles_1m, dataset_versions, data_imports/conflicts/errors, import_presets, derived_candles/builds, календари; модули continuous, aggregation, calendar, ingest/file_import, ISS-провайдер из `libs/providers`, задачи `aggregate.contract`, `import.iss`, `import.file`, `iss.*`, `verify.indicators` (если зависит от контрактов); страницы Import и Quality; CSV-импорт — позже отдельным importer при необходимости. Данные в БД не мигрируются: загружаются заново через importer.

**Ключи API.** Везде `instrument_id` и `timeframe` вместо `root_id/contract_id`; свечи: `GET /instruments/{id}/candles?tf=&start=&end=&limit=&tail=&as_of=` (срез знания по `close_time`). Загрузка: `POST /instruments/{id}/load` (период, TF) → задача `candles.load`; `GET /importer/tickers` проксирует список тикеров для UI.

## Этапы и декомпозиция
1. Контракт importer (OpenAPI) и сервис `apps/importer` с прокси к ISS (#172).
2. БД: новая модель, миграция с удалением старой (#173).
3. Ядро: клиент importer, задача `candles.load`, API инструментов и свечей (#174).
4. Движки, индикаторы, профили, сетки: ключ `instrument_id` (#175).
5. Статистика, аналоги, Forecast: ключ `instrument_id` (#176).
6. Бэктест: без контрактов, ролла и `step_price`, ключ `instrument_id` (#177).
7. Веб: Instruments (тикеры importer и загрузка), Chart/Replay/Backtest на инструментах, удаление Import и Quality (#178).
8. Удаление мёртвого кода и ADR (пометка заменённых), документация, проверка в браузере (#179).
